# Pilipuk Repair — Telegram-бот заявок

Бот для мастерской по ремонту компьютеров и ноутбуков в Киеве. Клиент оформляет заявку прямо в Telegram, мастер получает её с фото и AI-оценкой, ведёт по статусам, согласовывает цену и собирает отзывы.

Раньше в репозитории был бот-копирайтер для постов в канал. Этот проект полностью переписан под **приём и обработку заявок**.

---

## Что умеет бот

### Для клиента
- 🛠 Пошаговая заявка: тип техники, модель, проблема, фото, способ передачи, имя, телефон.
- 🤖 **AI-предварительная оценка** по описанию и фото (OpenRouter, бесплатная модель).
- 📋 «Мои заявки»: статус, цена, комментарий мастера, история.
- 💰 Согласование цены: мастер предлагает сумму, клиент нажимает «Погоджуюсь» или «Ні».
- 🔔 Автоматические уведомления при смене статуса.
- ⭐ Оценка работы и текстовый отзыв после завершения.
- 💵 Ориентировочный прайс, FAQ и контакты.
- 🛡 Защита от спама: не больше 3 активных заявок на пользователя.

### Для мастера
- 📲 Мгновенное уведомление о новой заявке с фото и AI-оценкой.
- 🏷 Кнопки статусов: в работу, диагностика, ждём детали, готова, завершена, отклонить.
- 💰 Установка цены + комментарий, отправка клиенту на согласование.
- 💬 Сообщение клиенту прямо из карточки заявки.
- 📊 Статистика: новые, активные, завершённые, выручка, средний чек, конверсия, рейтинг.
- 📤 Экспорт всех заявок в CSV (открывается в Excel).
- 🆕 Список новых/активных/всех заявок с пагинацией.

### Технические фишки
- Webhook-режим для хостинга + long polling локально.
- Health-check `/health` для Render/UptimeRobot.
- SQLite локально и PostgreSQL (Neon/Supabase) в продакшене.
- Автоматическое обновление описания и команд бота через Bot API — не нужно вручную менять их в BotFather.
- HTML-экранирование пользовательских данных, проверка прав админа, валидация телефона и суммы.
- Готовый `render.yaml` и `Dockerfile` для бесплатного деплоя.

## Быстрый старт локально (Windows)

1. Установите **Python 3.12**: https://www.python.org/downloads/  
   При установке включите **Add Python to PATH**.

2. Откройте PowerShell в папке проекта и выполните:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
Copy-Item .env.example .env
notepad .env
```

3. Заполните в `.env`:

```env
BOT_TOKEN=токен_от_BotFather
OWNER_ID=ваш_telegram_user_id
```

`OWNER_ID` проще всего узнать через [@userinfobot](https://t.me/userinfobot) до запуска. После запуска также работает команда `/id`.

4. Запустите:

```powershell
python bot.py
```

Без `WEBHOOK_URL` бот работает через **long polling**. Напишите ему `/start`.

### AI-оценка (необязательно)

1. Зарегистрируйтесь на https://openrouter.ai
2. Создайте ключ: https://openrouter.ai/keys
3. Добавьте в `.env`:

```env
OPENROUTER_API_KEY=sk-or-v1-...
AI_MODEL=openrouter/free
```

Если ключа нет — бот работает, просто без AI-оценки. Бесплатная модель может не поддерживать фото: тогда бот автоматически повторит запрос только по тексту.

## Деплой на бесплатный Render (не Railway)

Почему Render: есть бесплатный web service без карты, деплой из GitHub, поддержка Python и webhook. Render засыпает после 15 минут без запросов — это решается бесплатным пингом `/health` (ниже).

### Шаг 1. База данных Neon (бесплатно)

На бесплатном Render диск временный: SQLite потеряется при передеплое. Для реальных заявок нужен PostgreSQL.

1. Зарегистрируйтесь на https://neon.com (или https://neon.tech).
2. Создайте проект, например `repair-bot`.
3. Скопируйте **Connection string** вида:

```text
postgresql://user:password@ep-xxx.eu-central-1.aws.neon.tech/neondb?sslmode=require
```

Пароль в строке может содержать специальные символы — лучше скопировать строку целиком из панели Neon.

### Шаг 2. Загрузите код на GitHub

Создайте пустой репозиторий на GitHub (можно приватный) и загрузите файлы проекта. Варианты:

- **GitHub Desktop** — самый простой способ без командной строки.
- Через веб-интерфейс GitHub: «Add file → Upload files» (загрузите всё, кроме `.env`, `.venv`, `data`).
- Через git, если установлен:

```bash
git init
git add .
git commit -m "Rewrite bot for repair requests"
git branch -M main
git remote add origin https://github.com/ВАШ_ЛОГИН/repair-ai-bot.git
git push -u origin main
```

### Шаг 3. Создайте Render Web Service

1. Зарегистрируйтесь на https://render.com через GitHub.
2. Нажмите **New → Blueprint** (или **New → Web Service**).
3. Подключите репозиторий.
4. Render сам прочитает `render.yaml`. Если создаёте вручную:
   - **Runtime:** Python
   - **Build Command:** `pip install --upgrade pip && pip install -r requirements.txt`
   - **Start Command:** `python bot.py`
   - **Health Check Path:** `/health`
   - **Plan:** Free
5. Добавьте Environment Variables:

| Переменная | Обязательно | Значение |
|---|---|---|
| `BOT_TOKEN` | да | токен от @BotFather |
| `OWNER_ID` | да | ваш Telegram User ID |
| `DATABASE_URL` | да для продакшена | строка подключения Neon |
| `OPENROUTER_API_KEY` | нет | ключ OpenRouter для AI-оценки |
| `CONTACT_PHONE` | нет | ваш телефон |
| `CONTACT_USERNAME` | нет | `pilipuk_repair` |
| `AI_MODEL` | нет | `openrouter/free` |

Остальные значения уже прописаны в `render.yaml`. Необязательные `OPENROUTER_API_KEY` и `CONTACT_PHONE` можно добавить позже в разделе **Environment** — бот работает и без них.

6. Нажмите **Deploy**. Первый билд занимает 3–7 минут.

После деплоя:

- Откройте `https://ВАШ-СЕРВИС.onrender.com/health` — должно быть `{"ok": true}`.
- Отправьте боту `/start`.
- В логах Render будет строка `Webhook: https://.../webhook` — значит, webhook установлен автоматически (Render передаёт `RENDER_EXTERNAL_URL`).

### Шаг 4. Не давайте Render засыпать

Бесплатный Render останавливает сервис после 15 минут без HTTP-запросов. Telegram-webhook его разбудит, но первый ответ может задержаться на 30–50 секунд.

Бесплатное решение — внешний пингер:

1. Зарегистрируйтесь на https://uptimerobot.com (или https://cron-job.org).
2. Создайте HTTP(s)-монитор:
   - URL: `https://ВАШ-СЕРВИС.onrender.com/health`
   - Интервал: каждые 10 минут.
3. Готово. Сервис будет просыпаться и не уходить в сон.

Лимит Render Free — 750 часов в месяц. Один сервис, работающий круглосуточно, укладывается в лимит (≈744 часа).

> Если не хотите пингер — можно оставить сон. Заявки не потеряются: Telegram повторяет доставку webhook, а база в Neon сохраняет данные. Но ответы будут с задержкой после простоя.

> Состояния незавершённой формы хранятся в памяти процесса. После засыпания Render или передеплоя клиенту нужно начать заполнение заново через `/start`. Уже созданные заявки остаются в базе.

## Альтернативные бесплатные платформы

Проект можно запустить на любой платформе, которая умеет Python/Docker и даёт публичный URL.

### Koyeb
- Загрузите репозиторий, выберите **Dockerfile**.
- Укажите переменные окружения.
- После первого деплоя скопируйте публичный URL и добавьте `WEBHOOK_URL=https://...`.
- Передеплойте. `PORT` обычно подставляется платформой; если нет — `PORT=8080`.

### Fly.io
- Есть бесплатный лимит, но требуется привязка карты.
- `fly launch`, затем `fly secrets set BOT_TOKEN=... OWNER_ID=... DATABASE_URL=... WEBHOOK_URL=https://...`.
- Для SQLite нужен volume; для продакшена лучше Neon.

### Hugging Face Spaces (Docker)
- Работает, но Space засыпает и не предназначен для постоянных ботов. Подходит только для теста.

### PythonAnywhere
- Не рекомендуется для этого бота: бесплатный тариф ограничивает исходящие запросы и фоновые задачи.

## Важно про базу данных

- **Локально** по умолчанию: `sqlite+aiosqlite:///./data/repair_bot.db`.
- **На Render без `DATABASE_URL`**: SQLite работает, но файл исчезает при передеплое/рестарте. Для реальных заявок обязательно подключите Neon.
- **PostgreSQL**: просто задайте `DATABASE_URL`. Код сам преобразует `postgres://` и `postgresql://` в драйвер `psycopg`.
- Строка Neon должна содержать `?sslmode=require`.

## Как работает обработка заявки

1. Клиент заполняет форму.
2. Бот создаёт заявку с номером `R-00001` и отправляет мастеру карточку с фото.
3. Мастер нажимает статус:
   - 🛠 В работу
   - 🔍 Диагностика
   - 📦 Ждём детали
   - ✅ Готова к выдаче
   - 🏁 Завершить
   - ❌ Отклонить
4. Клиент автоматически получает уведомление.
5. Мастер может нажать **«💰 Вказати ціну»**, ввести сумму и комментарий. Клиент получает кнопки «Погоджуюсь / Не погоджуюсь». Если клиент согласовал цену по новой заявке, она автоматически переходит в статус «В роботі».
6. После завершения клиенту приходит запрос оценки 1–5, а затем — предложение добавить текстовый отзыв (по желанию).
7. Все заявки доступны в админ-панели, статистике и CSV.

## Частые проблемы

### «Не хватает переменных окружения: BOT_TOKEN, OWNER_ID»
Заполните `.env` локально или Environment Variables на хостинге. На Render переменные добавляются в **Environment**, а не в файл.

### Бот не отвечает после деплоя
1. Проверьте логи Render.
2. Откройте `/health`.
3. Убедитесь, что в логах есть `Webhook: ...`.
4. Проверьте, что сервис не спит (пингер).
5. Если ранее запускали polling-версию, остановите её: одновременно polling и webhook дают конфликт `Conflict: terminated by other getUpdates`.

### Ошибка базы данных
- Проверьте `DATABASE_URL`.
- Для Neon нужен `?sslmode=require`.
- Если в пароле есть `@`, `:`, `/`, используйте строку из панели Neon целиком или URL-encode пароль.

### AI не работает
- Проверьте `OPENROUTER_API_KEY`.
- Бесплатные модели имеют лимиты и иногда недоступны.
- Если модель не поддерживает фото, бот автоматически повторит запрос по тексту.
- AI-оценка не блокирует заявку: при ошибке заявка всё равно уходит мастеру.

### Данные пропали после передеплоя
На Render Free нет постоянного диска. Подключите Neon PostgreSQL и задайте `DATABASE_URL`. SQLite подходит только для локального теста.

### «Кнопка застаріла»
Кнопки из старых сообщений могут не работать после изменения статуса. Откройте заявку заново из админ-панели или раздела «Мои заявки».

## Безопасность

- Не коммитьте `.env` — он уже в `.gitignore`.
- Если токен попал в публичный репозиторий, перевыпустите его в @BotFather: `/revoke`.
- Админ-функции проверяют `OWNER_ID`/`ADMIN_IDS` на уровне фильтра роутера.
- Пользовательский текст экранируется перед вставкой в HTML.
- Webhook защищён `secret_token` (Telegram присылает его в заголовке).

## Что осталось от старого бота

- `TELEGRAM_BOT_TOKEN` поддерживается как fallback для `BOT_TOKEN`.
- `OPENROUTER_API_KEY` можно использовать тот же.
- `PC_REPAIR_CHANNEL_ID` и `WEB_DEV_CHANNEL_ID` больше не нужны: бот не публикует посты в каналы, а принимает заявки.
- Генерация/редактирование изображений и «ДО/ПОСЛЕ» удалены, потому что были заглушками без рабочей модели. Если нужны — их можно подключить отдельным платным image-API, не смешивая с заявками.
- Описание и команды бота обновляются автоматически при старте. Аватарку нужно один раз загрузить в BotFather вручную.
